📏 1. Analisi Strutturale e Dimensionale (URL e Query)
L'obiettivo di queste feature è individuare payload troppo grossi o complessi rispetto alla normale navigazione umana.

url_length / path_length / query_length: Misurano la lunghezza delle varie parti dell'URL. Valori anomali indicano spesso tentativi di Buffer Overflow o lunghe SQL Injection.
num_query_params: Quanti parametri ci sono (es. ?a=1&b=2). Un numero eccessivo indica fuzzing o test automatici.
avg_query_param_len / max_query_param_len: La lunghezza media e massima dei parametri. Un parametro di 500 caratteri non è un ID legittimo, è codice iniettato.
num_path_segments: Quante "cartelle" attraversa l'URL (es. /a/b/c/). Picchi anomali indicano scanner di directory.
max_path_segment_len: La lunghezza del singolo segmento di percorso più lungo. Cattura tentativi di exploit infilati direttamente nel nome della rotta.
🔣 2. Analisi Tipografica (Caratteri speciali)
Gli attacchi web fanno un uso massiccio di punteggiatura (virgolette, parentesi, uguali).

num_digits_url / num_digits_body: Quantità di numeri. Serve come baseline statistica.
num_special_chars_url / num_special_chars_body: Quanti caratteri speciali ci sono in totale.
special_char_ratio_url / special_char_ratio_body: Il rapporto tra caratteri speciali e testo normale. Un'altissima densità di caratteri speciali è un indicatore quasi certo di Cross-Site Scripting (XSS) o SQL Injection.
num_uppercase_in_query: Numero di lettere maiuscole. Spesso usate per bypassare filtri WAF rudimentali sensibili al maiuscolo/minuscolo.
🧠 3. Analisi Entropica (Rilevamento Offuscamento)
L'entropia di Shannon misura il "disordine" matematico in una stringa.

url_entropy / path_entropy / query_entropy / body_entropy: Stringhe con entropia molto alta sono tipicamente casuali, criptate o offuscate (es. malware o payload Base64). Il traffico umano (es. /articolo-di-oggi) ha entropia molto bassa e prevedibile.
🕵️ 4. Pattern Malevoli Noti (Firme comportamentali)
Individua token esatti all'interno del traffico (senza bloccarli a prescindere, ma facendoli pesare matematicamente sull'anomalia).

path_traversal_tokens_url / path_traversal_tokens_body: Cerca sequenze come ../ o %2e%2e/ usate per accedere a file di sistema critici (es. /etc/passwd).
sql_keyword_count_url / sql_keyword_count_body: Conta parole chiave del database come UNION, SELECT, --, OR 1=1.
xss_token_count_url / xss_token_count_body: Conta tag HTML/JS nocivi come <script>, onload=, alert().
🥷 5. Tecniche di Evasione Avanzate (WAF Bypass)
Feature progettate specificamente per catturare hacker esperti che cercano di "nascondersi".

ratio_encoded_chars_url: La percentuale di URL codificata in URL-Encoding (es. %20). Un eccesso indica la volontà di nascondere il testo ai filtri di sicurezza.
has_double_encoding: Rileva il doppio encoding (es. %2527). Tecnica di bypass famosissima per ingannare i firewall che decodificano la stringa una sola volta.
has_null_byte: Rileva il carattere di terminazione %00 (o null byte). Utilizzato storicamente per troncare i controlli sulle estensioni dei file backend (es. file.php%00.jpg).
num_duplicate_params: Rileva parametri ripetuti (es. ?id=1&id=2). Segnala attacchi di HTTP Parameter Pollution volti a confondere il backend.
📦 6. Analisi del Payload (Body)
Controllo di cosa viene caricato verso il server tramite form o API (POST/PUT).

method_code / content_type_code: Traduzione in numeri (per l'AI) del tipo di verbo HTTP e del formato dati (JSON, form, XML).
has_body / body_length: Indica la presenza e la stazza del payload. Un body spropositato può essere un attacco DoS o un buffer overflow.
num_body_params / avg_body_param_len: Come per l'URL, ma calcolato sui parametri POST.
body_to_url_length_ratio: Rapporto tra le dimensioni del body e dell'URL. Squilibri totali indicano pattern di rete non umani.
has_base64_pattern: Rileva la presenza di lunghe stringhe compatibili con il Base64, comunissimo per caricare Web Shell (script PHP malevoli) mascherate.
num_semicolons_body: L'abuso del punto e virgola nel body indica spesso Command Injection o codice JS forzato.
📐 7. Coerenza Strutturale del Protocollo
Controlla se l'attaccante ha forgiato la richiesta a mano sbagliando la sintassi standard HTTP.

method_body_mismatch: Rileva se una richiesta GET (che dovrebbe solo leggere) sta trasportando un Body illecito.
content_type_body_mismatch: Segnala se c'è un Body pesante ma manca l'intestazione Content-Type (o viceversa). Le vere app/browser non commettono mai questi errori, gli script di hacking approssimativi sì.
